## Open findings (2026-10-24)

### CRITICAL — none

### HIGH

**H1 — `local_ci.py --full` vs CI lint scope divergence** *(carries forward item 13)*
`local_ci.py` in `--full` mode lints the entire tree (`.`) including `scripts/neezy_anim.py`, which is an intentionally permissive terminal animation demo with 2264 style violations (single-line `if: return`, semicolon-chained statements, `%` formatting for ANSI). CI lints only `neezy_app neezy_backend tests forex_signals.py` and is green. A contributor running the documented `python local_ci.py --full` pre-push gate will always fail, even though CI would pass. **Fix:** either (a) add `scripts/neezy_anim.py` to `per-file-ignores`/`exclude`, or (b) reformat the file to comply. Recommendation: exclude animation demos from the strict gate and document them as `per-file-ignores` — they are visual art, not library code.

**H2 — Documentation truth drift** *(carries forward item 5, re-verified)*
`PLAN.md` marks Batch 5 (`evals/` harness) and Batch 8 (docs deliverables) as "Completed", but `evals/` does not exist and `docs/AGENT.md` explicitly says "This checkout has no `evals/` directory or `evals/run_evals.py`". `DECISIONS.md` Decision 5 promises `neezy_backend/prompts/` which does not exist. `PROGRESS.md` and `CHANGELOG.md` overstate completion vs `ROADMAP.md` (57/500 done, not 500). This is dangerous for future autonomous runs that trust these files.

**H3 — Mobile port missing ORDERS parity** *(carries forward item 6, re-verified)*
Desktop `NAV` has 10 entries (`CHAT, SYMBOLS, CHART, SIGNALS, INSIGHTS, TOOLS, ORDERS, ALERTS, HISTORY, SETTINGS`). `neezy_mobile/screens.py::TAB_CLASSES` has 9 (missing `ORDERS` + one tools/settings mapping variance). Its module docstring claims parity with `NAV`. Users on Android cannot access the order desk at all. The Kivy port is built and released on every `main` push, so this is user-visible.

### MEDIUM

**M1 — `forex_signals.py` silent shim with no deprecation path** *(roadmap #26)*
`forex_signals.py` is a bare `from neezy_app.launcher import main` shim kept for "older instructions" with no warning. New users are not guided to the installed `neezy` command, and `python -m neezy_app` vs `forex_signals.py` creates two entry points with no docs link.

**M2 — Animation scripts violate project style but are not excluded** — see H1.

**M3 — `docs/ARCHITECTURE.md` duplicates and contradicts root `ARCHITECTURE.md`**
Root `ARCHITECTURE.md` is the verified 10-section authoritative reference (with cloud executor plane). `docs/ARCHITECTURE.md` is a stale pre-split diagram kept "for history". No header in the stale file warns readers; `CONTRIBUTING.md`'s code map points to root `ARCHITECTURE.md`, but external links may hit the stale copy.

**M4 — No coverage or dependency-pinning guardrails in CI**
CI runs lint → test → smoke → build but does not check: (a) test coverage thresholds (no `coverage.py` gate), (b) `requirements-*.txt` pinning vs `pyproject.toml` drift, (c) CHANGELOG updates on behavior changes. Roadmap items #44, #83, #86 flag this.

**M5 — Snapshot capture logic is scattered** *(roadmap #24)*
`database.py::save_snapshot` is a one-line delegate to `repositories.SnapshotRepo`, but `storage.py`, `mcp_tools.py`, and `tools.py` each re-implement "capture current market snapshot" logic slightly differently. No shared `capture_snapshot()` helper.

**M6 — Menu rendering width is global, not data-driven** *(roadmap #30)*
`neezy_backend/ui_style.py::_WIDTH = 60` is a module constant; all panels use the same width. Narrow terminals (Termux), wide terminals, and CI logs get the same layout. `output_width()` exists but is not wired into menu rendering.

**M7 — Backend capability flags exist but are under-utilized** *(roadmap #32)*
`neezy_backend/capabilities.py` exposes `BACKEND_FEATURES` for mt5/kivy/numpy/fts5/local_llm but does not expose `__version__`/`API_VERSION` and is not imported by CLI `doctor` or `status` where it would be most useful.

**M8 — No timing/cost instrumentation behind `NEEZY_TIMING` flag** *(roadmap #81)*
`diagnostics.py` has `system_info`/`build_bundle` but no `timed()` helper, no `NEEZY_DEBUG`/`NEEZY_TIMING` env-flag to log per-command duration. Makes perf regressions invisible.

**M9 — CI does not enforce changelog or produce test summary artifacts** *(roadmap #82, #86)*
No test-output summary is uploaded, no changelog check. PRs changing behavior without a CHANGELOG entry pass CI silently.

**M10 — Settings have no migration version** *(roadmap #91)*
`AppSettings` has no `schema_version`/`config_version` field. Old configs are handled by `from_dict` ignoring unknown keys, but there is no explicit migration that can rename/deprecate a field with a warning. Future breaking renames will be ad-hoc.

**M11 — Watchlist import/export is manual-only** *(roadmap #94)*
Watchlist is set via `watchlist_extra` comma string in Settings; there is no CLI `neezy-cli markets watchlist export/import` or UI file dialog. Users share watchlists by copying raw strings.

**M12 — Dry-run flag is CLI-only for MT5** *(roadmap #100)*
`neezy-cli mt5 order --dry-run` exists, but there is no global `AppSettings.dry_run` that gates all order paths (CLI + desktop + future executor). Desktop ORDERS page cannot be set to never send.

### LOW

**L1 — `.devcontainer/devcontainer.json` is minimal** *(roadmap #84)*
Only installs `.[dev,mt5-remote]`; does not set `NEEZY_HOME`, forward the status API port, or include `postStartCommand` for `rux`. Workable but not polished.

**L2 — Config `watchlist_extra` validated as string but not as symbol list** — invalid symbols (e.g. typo `frxEURUS`) are silently stored; `markets.watchlist()` would reject them only at use time with a vague message.

**L3 — Duplicate test fixtures across `test_*` modules** *(roadmap #31)*
Candle list builders (`make_candle`, `_candles`, `CANDLE` tuples) appear in 8+ test files with tiny variations; no shared helper.

**L4 — Knowledge base caching is module-local** *(roadmap #134 area)*
`knowledge.py::KnowledgeBase` re-parses JSONL on every read; no TTL.
